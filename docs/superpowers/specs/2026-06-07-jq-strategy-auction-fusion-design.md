# 聚宽原始策略融合首板1进2竞价确认设计

## 背景

当前目标是增强 `聚宽策略/原始策略_早盘买尾盘出.py` 的选股质量，让它吸收 `聚宽策略/首板1进2.py` 的核心优点，但不把原策略整体改造成首板接力策略。

原策略的优势是盘前复盘打分框架清晰，交易节奏简单：盘前选股、早盘买入、尾盘只卖不买。首板1进2策略的优势是对强势股做了更严格的次日资金承接确认，尤其是集合竞价确认、过热过滤和左侧量能校验。

## 设计目标

融合后的策略应保持原策略的主节奏：

1. 盘前基于前一交易日数据生成候选股。
2. 09:26 对候选股做集合竞价确认。
3. 9:30 只买竞价确认通过的股票。
4. 14:50 保持尾盘只卖不买。

成功标准：

- 原策略仍最多持有 4 只股票。
- 原策略不强行满仓；竞价确认不足时允许少买或空仓。
- 首板1进2的优点作为确认层和风控层加入，而不是替代原策略全部选股体系。
- 不引入 ML 风控和午盘卖出，避免扩大改动范围和改变交易风格。

## 推荐方案

采用“两阶段选股 + 竞价确认”。

盘前阶段由原策略负责发现强势候选：

- 保留现有五维打分、热度、市值、量价、位置、均线粘合、EMA 趋势等评分。
- 将最终直接买入的 Top4 改为候选池，例如 Top8 或 Top12。
- 候选池写入 `g.pre_target_list`。

竞价阶段由首板1进2逻辑负责验货：

- 新增 `my_auction_confirm`，运行在 09:26。
- 从 `g.pre_target_list` 中筛选出 `g.final_buy_list`。
- 竞价确认优先参考首板1进2中的 `CONDITION_RULES`、昨日成交额、竞价涨幅、竞昨比、市值、开盘价和左侧量能。

买入阶段保持原策略风格：

- `my_morning_trade` 不再直接买 `g.target_list`。
- 改为买 `g.final_buy_list`，最多 4 只，等权分配可用现金。
- 如果 `g.final_buy_list` 为空，则当天不买入。

尾盘阶段保持不变：

- `my_afternoon_trade` 继续在 14:50 卖出可卖持仓。
- 不引入首板1进2的 11:25 和 13:30 卖出逻辑。

## 吸收的首板1进2模块

优先吸收以下逻辑：

- `CONDITION_RULES`：集合竞价涨幅和竞昨比规则。
- `get_hl_count_df`：统计涨停和一字/T 字板。
- `filter_excessive_limit_up`：过滤近 10 日 3 次以上一字/T 字板。
- `filter_excessive_increase`：过滤近 5 日波动超过 40%。
- `filter_excessive_limit_days`：过滤近 5 日涨停 >= 4 天。
- `filter_below_n_high`：要求接近 100 日高点，保留强势结构。
- `calculate_zyts`：用于左侧量能校验，避免缩量假突破。

原策略已经有一部分相似特征。实现时应优先复用或对齐现有逻辑，避免重复统计同一指标。

## 暂不吸收的模块

暂不吸收 ML 在线学习：

- 当前首板1进2代码中 ML 输出语义和日志描述存在潜在歧义，容易把盈利概率当成亏损概率使用。
- ML 风控需要更长回测验证，不适合作为第一版融合内容。

暂不吸收午盘卖出：

- 原策略核心是早盘买、尾盘出。
- 引入 11:25 和 13:30 卖出会改变策略持仓周期和收益来源。

暂不改造成纯首板策略：

- 原策略不应被强制限定为“昨日涨幅 > 7%”股票池。
- 首板条件作为加分和竞价确认依据，而不是唯一入口。

## 数据流

1. `before_trading_start`
   - 获取基础股票池。
   - 计算原策略评分。
   - 应用必要的过热过滤。
   - 生成 `g.pre_target_list`。

2. `my_auction_confirm`
   - 读取 `g.pre_target_list`。
   - 获取昨日成交额、成交量、市值、流通市值。
   - 获取 09:15-09:26 集合竞价数据。
   - 计算竞价涨幅 `cur_ratio` 和竞昨比 `auction_ratio`。
   - 命中条件后写入 `g.final_buy_list`。

3. `my_morning_trade`
   - 读取 `g.final_buy_list`。
   - 继续跳过停牌、涨停、跌停和开盘偏离过大的股票。
   - 等权买入通过确认的股票。

4. `my_afternoon_trade`
   - 保持当前尾盘卖出逻辑。

## 仓位规则

第一版采用保守规则：

- 通过竞价确认 4 只及以上：买前 4 只。
- 通过竞价确认 1-3 只：只买通过的股票，不补足。
- 通过竞价确认 0 只：空仓等待。

这样可以最大限度保留首板1进2的资金承接确认优势，避免为了满仓买入质量下降的票。

## 风险与注意事项

- 集合竞价数据依赖聚宽 `get_call_auction`，回测区间和平台权限可能影响可用性。
- 候选池过小会导致竞价确认后经常空仓，因此盘前候选建议先用 Top12。
- 竞价规则来自首板1进2，但原策略候选不一定全是首板股，实现时需要允许部分规则作为“确认强度”，而不是机械要求所有票完全符合首板条件。
- 第一版应避免一次性加入 ML、午盘卖出和复杂仓位曲线，减少归因困难。

## 验证计划

实现后至少做以下验证：

- 静态检查：确认新增函数名、全局变量和定时任务无拼写错误。
- 编译检查：对策略文件运行 Python 编译检查，排除语法错误。
- 逻辑检查：检查 `g.pre_target_list`、`g.final_buy_list`、`g.limit_ups_dict` 的生命周期。
- 回测检查：在聚宽环境跑一段近期回测，观察候选数量、竞价通过数量、买入数量和空仓天数。
